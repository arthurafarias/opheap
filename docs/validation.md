# Validation record — 0.1.0 MVP

This page records what was actually exercised for the generated prototype. It is deliberately narrower than the 1.0 target in the SRS.

## Builds

Validated in the generation environment with:

- GCC 14.2.0;
- Clang (Swift toolchain build available in the environment);
- CMake 3.31.6;
- C++23;
- `-Wall -Wextra -Wpedantic -Werror` on GCC and Clang.

Both compilers built the library, examples and self-registering test executable.

## Class/subsystem tests

The current aggregate suite contains **32 tests, 32 passing**. Test groups cover:

- `observer` / `observable`;
- `property`;
- `string`;
- `vector`;
- `map`;
- `value` / `array` / `object` behavior;
- `observing_resource`;
- `codec`;
- `storage`;
- `journal`;
- `snapshot_store`;
- `transaction`;
- `heap`;
- storage fault injection across partial append, failed durability barrier and interrupted checkpoint replacement.

The aggregate test translation unit is generated by CMake from every `tests/opheap/testing/*_test.hpp` header.

## Sanitizers

The same 32 tests pass with AddressSanitizer and UndefinedBehaviorSanitizer enabled (`detect_leaks=1`).

## Persistence tests exercised

- create/mutate/commit/close/reopen;
- abort leaves no committed state;
- deterministic same-root optimistic conflict;
- independent named roots;
- actual multi-threaded independent-root commits;
- torn final WAL bytes;
- torn COMMIT record (transaction not published);
- complete committed-record checksum corruption;
- checkpoint followed by repeated restart/recovery;
- partial WAL append injection;
- failed durability barrier injection and live-heap poisoning;
- failed checkpoint atomic replacement followed by recovery from the retained WAL.

## Installation

The project was installed to a clean prefix and consumed from a separate CMake project with:

```cmake
find_package(opheap CONFIG REQUIRED)
target_link_libraries(consumer PRIVATE opheap::opheap)
```

The consumer compiled and executed successfully.

## Benchmark smoke test

The included strict-durability microbenchmark was executed for 100 small commits. Its numbers are stored under `validation/`; they are **smoke-test measurements from a container environment and are not product performance claims**.

## Important MVP limitations

The following are intentionally not claimed complete:

1. Persistence granularity is a complete named Variant root, not individual pages/extents.
2. `observing_resource` observes allocation topology only; unmodified STL element writes are not observable.
3. There is no bounded committed-state cache/eviction implementation yet.
4. The fault matrix covers representative write/barrier/checkpoint failures, not process termination after every individual machine instruction/barrier boundary.
5. Cross-version file-format migration tooling is not implemented yet.
6. External database benchmark adapters are not implemented yet.
7. The Boost.Beast credentials REST service is documented as the next service integration, not included as production server code in 0.1.0.

These limitations are architectural roadmap items rather than hidden assumptions.
